## Before you submit

1. **Arabic brand name.** The listing spells the brand وددى and calls XP
   نقاط الخبرة, as `ar.json` does since commit e7039ed. If either changes
   again, update the name, description and What's New together.
2. **Live modules.** The listing covers food, grocery, pets, Spots and XP.
   Pharmacy, parcel and eCommerce exist in code but are left out; add a line
   only for a module that's switched on in production.
3. **Deploy-pending features.** Pets, the scratch card, the XP fixes and the
   new live tracking all wait on a backend deploy (`docs/plans_index.md`). If
   any of them won't be live on launch day, remove its section or bullet.
   Apple can reject a listing that describes features the reviewer can't find
   (Guideline 2.3.1).
4. **Location keywords.** `maadi` / `المعادي` assumes the launch zone is Maadi.
   Swap in your real zones, and add new ones as you expand.
5. **No competitor names** in keywords (Guideline 2.3.7). Talabat, Elmenus and
   Breadfast are deliberately left out.
6. **Reviewer access.** Out-of-zone users can browse but can't check out, so put
   a test account with an in-zone address in App Review Information.
7. **Contest rules (Guideline 5.3).** The Spots draw and prize screens show
   `spots_sponsor_note` ("Waddy runs this draw. Apple and Google are not
   sponsors…") next to the odds and one-prize rules. Keep it if that copy is edited.
8. **Screenshots.** The phone in every screenshot must show real UI from the
   submitted build. Don't upload the Arabic screenshot set until it uses Arabic
   app screens, or Apple can flag it as mixed-language.
